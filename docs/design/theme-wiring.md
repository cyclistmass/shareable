# Theme art wiring (#88)

The shipped Default/Pirate wiring on 0.3.0 is below. Space is an asset/API addition;
no settings, picker, Look & art, game rules, names or card text change here.

| Object | Selection site and flag |
|---|---|
| Saved set | `EnvSettings.pirateTheme` is the persisted Boolean; `MainActivity` passes it to the consumers below. |
| Painted terrain | `MainActivity` tile image lists / `TerrainArt`; shared, no Pirate flag. |
| Tilted terrain | `Tile3dArt.TERRAINS`, `TileSprites3d`; shared, no Pirate flag. |
| Number plates/digits | Flat canvas drawing; `LiveNumberGlb` and `livePlacements` use `number_plate`/`digit_N`; shared. |
| Homestead / Town | `BuildingSprites(res, pirate, chivalry)` → `BuildingArt.homestead/town(pirate)` → `bld_default_*` or `bld_pirate_*`. |
| Roads | `BuildingArt.roadV/roadP30/roadM30(pirate)`; direction chosen by `BuildingSprites.roadFor`. |
| Ramparts | `BuildingArt.ramparts(pirate)`, three heights, selected by `rampartsHeight`. |
| Capitals | `BuildingArt.capitals(pirate)` ordered Guilds/Academy/Crown; `capitalIndex` converts engine tracks. |
| Knight sprites | `KnightArt.levels(pirate)` through `BuildingSprites`; `MainActivity.knightsPirate/knightsNormal` provide legacy fallbacks. |
| Knight activation | `liveKnightModel(state, v, pirate)` appends `_inactive`; flat legacy sprites also dim inactive bodies. |
| Knight cards | `GuideArt.knightCard(level, pirate)` → `card_knight_{normal,pirate}_N`. |
| Resource / commodity cards | `ALL_CARD_ART`, the Ledger pages (`card_<name>`); shared, no Pirate flag. |
| Fortune cards | `GuideArt.fortuneArt(card, pirate)` → Ledger `card_fortune_<name>`, drawn plain; only Sentinel switches to the pirate knight card. |
| Progress cards / deck backgrounds | `CkPlay`, card guide and card-face drawing; the commodity paintings (`COMMODITY_PICTURE`, `card_paint_*`) and deck colours. |
| Production dice | `DiceArt.face/tumble(red, pirate)` → NR/NI or PR/PB; used by `Hud` and `RollingDice`. |
| Event die | `DiceArt.eventFace/eventTumble(pirate, eventDieStyle)` → AE or PE/PE1/PE2/PE3; source face numbering remapped to engine tracks. |
| Bandit | `BANDIT_SPRITES` / `bandit_tilt_N`; live `bandit.glb`; shared. |
| Merchant | `MerchantToken.kt` draws the token procedurally; shared. |
| Ports | `PortArt.TYPES` via `BuildingSprites.ports`, generic then five resources; shared. |
| Sea / cliffs | `Sea`, `SeaArt`, `ocean_tile` / `cliff_top_*`; live `sea.glb`; shared. |
| Boats / Raiders | `SeaArt.sloop`, trim and `raiders` heading/tilt arrays, plus legacy sprites; shared. |
| Gulls / whale | `SeaArt` and `Sea` scenery plus `CritterModules.load`; shared. |
| Modular critters | `assets/critters/<id>/critter.json` and `frames/`; global loader currently loads every immediate module, no theme flag. |
| Live models | `livePlacements(state, pirate, lod)` builds Default/Pirate building/knight names, shared terrain LOD0/1; `LiveBoardView` opens `assets/filament/<model>.glb`. |

## Space lookup contract

`SpaceArt.kt` is the public selection table; `SpaceArtData.kt` is generated by
`python tools/import_space.py <space-theme>`. A later ArtSet dispatcher can call
`SpaceArt` for SPACE and keep the existing Default/Pirate functions for the other sets.
No second settings enum is introduced here, avoiding ownership conflicts with the picker branch.

- `tile(resource, lod)`, `numberPlate(number?)`, `road(direction)`, `homestead`, `town`,
  `ramparts(height)`, `capital(track)`, `knight(level, active)`, `bandit`, `merchant`,
  `port(resource)`, `boat`, `raidersShip`, `sea`, `cliff`, `lane` return a `Sprite`.
- Each sprite gives resource IDs for all 18 authored views, a complete asset path,
  frame width, centre/contact height, pixel dimensions and separate shadow/body/trim.
  Neutral roles have full/shadow layers. `legacyTilt(0..7)` samples 0,2,5,7,10,12,15,17;
  `legacyPiece()` adapts tinted layers to `BuildingArt.Piece`, but its frame size must still be honoured.
- `resourceCard(0..7)`, `fortuneCard(0..4)`, `progressCard(0..24)`, `deckBack(track)`,
  `cardBack`, `knightCard(level)` return drawable IDs. The first 42 use existing unlettered
  `cards/art` renders centred on 278×390 transparent canvases. Three knight previews use
  complete neutral full renders on 256×360 canvases. Existing UI owns labels and frames.
- `diceFace(red, value)` and `eventFace(engineFace)` return face IDs. Event source faces
  map **1,2,3,6,5,4** to engine 0..5. `die(red)` and `eventDie` supply static views/models.
- `sprites`, `models`, `cards` enumerate the catalog; `model(role)` returns a full asset path.
  All 164 original GLBs are retained byte-for-byte, including the 42 physical card models
  and 42 illustration scenes. **Do not display the physical `card_*` GLBs as runtime cards:**
  their embedded textures contain provisional titles. Use the unlettered drawable lookups.
- `critters` returns five module paths beneath `critters/space/space_<id>`.
  Read each `critter.json` and pass it and its `frames/` listing to `CritterModules.module`.
  Splitting strips, adding `frames.span`, converting `loop` to `mode`, and adapting the
  turtle anchor/stage schema makes them compatible with the current parser.

## Hooks needed

- **Picker/EnvSettings/MainActivity:** route the new ArtSet selection to this table; add Space to Inventory
  only in the picker branch. No protected files were changed in this import.
- **Flat board:** draw using each sprite's `frameUnits` and centre, interpolate over 18 views or use
  `legacyTilt`; draw the supplied shadow separately, before body and fixed trim. Do not rotate a shadow
  with a road. Ports/Bandit are neutral even though their source meshes have WoodBody.
- **Live placements/MainActivity/LiveBoardOverlay:** use Space model paths, the +0.22 deck height,
  plate offset (+0.36,+0.30), explicit active/inactive knights, and source frame/size contracts.
  Preserve the approved approximately 0.3-unit island channels. Do not reuse the current +0.45 plate Y
  or add the old two-disc knight pedestal blindly. LOD0 and LOD1 intentionally share the lean source mesh.
- **Live renderer:** batch static Space placements with `SpaceBoardBatch.build(instances, openAsset)`;
  feed its GLB bytes to gltfio, off the UI thread, and rebuild after transforms or ownership change.
  Supply the same final rigid/uniform-scale matrix used for drawing and linear RGB tint only for
  owner-coloured pieces. The result preserves normals, vertex colours, all triangles and material
  properties. It rejects animation, textures and unbaked node transforms. Animated critters stay separate.
  **Do not enable Space by only substituting file names:** the unbatched worst case is 797 primitives;
  the tested batched four-player board is 7 static primitives plus at most 18 critter primitives.
- **Critters:** select only the selected theme's modules and cap their combined population at
  `SpaceArt.MAX_CRITTERS` (3); retain the turtle's fixed board-centre anchor and animate only its clips.
  Five available module types do not mean five simultaneously enabled populations.
- **MerchantToken/CkPlay/BoardHud/TurnReport:** choose Space icon/card resources without changing the
  current player-facing names, commodity rules or card descriptions.
- **Dice/RollingDice:** source art contains static views and face models, not tumbling loops. Hold a
  supplied face or animate the die GLB; camera tilt frames are not a fabricated tumble animation.
- **Boats/Raiders:** board sprites have one authored heading; the separate critters have eight.
  Use model heading transforms for 3D; a flat renderer must not invent sixteen rendered headings.

## Test plan

1. Unit/rules: resolve every resource ID/path, compare Default building roles, cover six terrains,
   both knight states, all cards/dice and critter clips; parse GLBs and test worst four/six-player batches.
2. Random play: run existing engine/AI fuzz suites (base and Age of Chivalry) and dice fairness tests.
3. Break-it: reject unknown roles, invalid indices, malformed/unsupported GLBs and invalid transforms
   without changing the lookup table; run existing illegal-action suites and reference fixtures.
4. Device: install the final APK, enter through the start screen, screenshot and smoke-test the existing
   app; run monkey. Space Inventory/board readability and runtime GPU profiling require the hooks above.
